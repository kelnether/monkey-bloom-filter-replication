# 小组学习与协作指南

## 1. 第一轮组会：统一项目理解

建议 60–90 分钟，不依赖组员已有数据库系统经验。

1. 读 [README 项目简介](../README.md#项目简介)，确认主复现对象只有 Monkey。
2. 用口头例子说明 Bloom filter 的“可能存在”和“一定不存在”，区分误报与漏判。
3. 用三层数据手工走一次成功查询和一次失败查询，分清过滤器检查与数据页访问。
4. 运行 README 中的测试命令，打开既有 HTML 报告，检查轴和单位。
5. 共同指定工作包负责人和审阅者；记录仍不理解的公式或代码。

会议后，每位组员应能回答：“为什么相同 bits/key 不是每层相同字节？”“为何所有层 FPR 相加对应未命中查询成本？”“为什么当前结果不能叫 SSD 加速？”

## 2. 最小知识清单

| 知识 | 掌握到什么程度 | 对应代码 |
|---|---|---|
| Python | 列表／字典、类、排序、二分查找、文件与测试 | 全项目 |
| 位与字节 | 8 bit=1 byte；设置和读取单个位 | `bloom.py` |
| Bloom filter | 插入、探测、误报、k/n/m 的意义 | `bloom.py` |
| LSM 基础 | 内存缓冲、run、level、查询顺序；概念上理解合并 | `store.py` |
| 数学与优化 | 指数、对数、期望、约束；知道 KKT 解的用途 | `allocation.py` |
| 实验设计 | 控制变量、配对比较、随机种子、均值与标准差 | `experiments.py` |
| 模型解释 | 假设、近似、边界、预测与测量的区别 | `model.py` |

第一阶段无需 SQL、事务、分布式共识或机器学习。不要因扩展论文出现复杂技术，就将它们全部加入当前范围。

## 3. 代码阅读顺序

先读 `bloom.py` → `allocation.py` → `store.py`，然后看 `tests/test_core.py`。能解释一次查询后，再读 `experiments.py` → `model.py` → `plotting.py`。不建议从上游 ML 目录开始。

每人选一个小例子记录：输入、过滤器预算、返回值、逻辑访问数，以及对应公式。上游参考和本地改写必须结合 [来源说明](../THIRD_PARTY.md) 阅读。

## 4. 四个工作包

| 工作包 | 负责人 | 审阅者 | 产出与完成标准 |
|---|---|---|---|
| A 理论与分配 | 待填写 | 待填写 | 说明优化目标、零预算、整数取整；核对一个手工例子 |
| B 过滤器与数据 | 待填写 | 待填写 | 解释位数组、查询提前结束、页访问计数；通过正确性测试 |
| C 实验与图表 | 待填写 | 待填写 | 冻结正式配置、运行多种子、补层数曲线、标注预测与实测 |
| D 文献与整合 | 待填写 | 待填写 | 相关工作、报告、演示和运行说明；让另一位组员复跑 |

两人组可合并 A+B、C+D；三人组可由所有人共同承担 D。全员都应理解主论文核心观点，而不是只负责排版或只运行命令。

## 5. 四个里程碑

| 阶段 | 建议任务 | 完成证据 |
|---|---|---|
| M1 理解与启动 | 共同阅读、安装、测试、分工 | 组员能解释基线和测量单位 |
| M2 方法审核 | 对照论文推导与代码，检查预算和零空间行为 | 公式—函数对照笔记与通过的测试 |
| M3 正式实验 | 确定配置和种子，保存一次完整运行，解释模型偏差 | 数据、CSV、图表、配置和元数据完整 |
| M4 写作与演示 | 完成相关工作、方法、结果、局限和贡献表 | 另一名组员按 README 成功重跑 |

具体日期以课程截止时间为准。建议先保证核心实验证据完整，再考虑附录 C 或偏斜查询扩展。

## 6. 协作约定

- 正式配置用新文件保存，结果用新目录；不覆盖他人的实验。
- 每次修改说明“原因、影响、验证方法”，避免同时修改算法和多个实验变量。
- 结果讨论先检查单位、数据规模、预算和查询分布，再比较曲线高低。
- 旧结果与修改后的源码分开；运行时保存的指纹帮助确定结果对应版本。
- 合并前由另一名组员解释关键变化。使用 Git 时可以按工作包开分支；此文档不代表已创建远程仓库。
- 保留代码与写作贡献、第三方复用和辅助工具使用记录，按课程政策如实说明。

## 7. 最终报告建议结构

1. Introduction：研究问题和范围。
2. Background & Related Work：Bloom filter、LSM、多篇文献的角色。
3. Method：优化目标、分配算法、静态布局、模型假设。
4. Experimental Setup：输入、参数、基线、配对与指标。
5. Results：误报／访问数、参数变化、预测偏差。
6. Limitations：静态布局、逻辑访问、Python 开销、未覆盖的系统组件。
7. Reproducibility & Contributions：运行命令、版本、数据与组员贡献。
